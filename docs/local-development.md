# Local development

The current development baseline is a laptop with VS Code and directly installed services. Docker, Docker Compose, Kubernetes and MinIO are not required.

## Required now

- Git
- Node.js 25.9.0
- npm 11.6.2
- PostgreSQL 18.x
- VS Code (preferred)
- Access to the Dotin Nexus npm repository

Run:

```bash
npm run workstation:check
```

The runtime check requires Node `>=25.9.0 <26` and npm `>=11.6.2 <12`.

## npm workspaces

The root `package.json` owns the workspace list:

```text
apps/*
packages/*
```

Turborepo remains the task orchestrator. npm is the only package manager for the active workstation baseline. Do not create or commit `pnpm-lock.yaml`.

The canonical dependency lockfile is `package-lock.json`. It must be generated by npm 11.6.2 against the required Nexus and committed only after install/lint/typecheck/test/build validation succeeds.

## Required npm registry

This repository is intentionally pinned to:

```text
https://nexus3.dotin.ir/repository/Dotin-NPM/
```

The root `.npmrc` is committed so `npm install` and all workspace dependency resolution use this Nexus. Do not override the registry to `registry.npmjs.org` during normal development.

Before installing packages, verify both the effective npm configuration and Nexus package access:

```bash
npm run registry:check
```

The `.npmrc` keeps TLS verification enabled and applies bounded retry/timeout settings for the internal Nexus.

If Nexus authentication is required in the developer environment, configure credentials only at the user/machine level or via environment variables. Never commit tokens, passwords, `_auth`, or `_authToken` values.

Installation analytics from Scarf are disabled at the root package level.

## Clean migration from the previous pnpm checkout

On a workstation that previously installed this repository with pnpm:

```powershell
Remove-Item pnpm-lock.yaml -Force -ErrorAction SilentlyContinue
Remove-Item node_modules -Recurse -Force -ErrorAction SilentlyContinue
npm cache verify
npm install
```

Do not reuse the pnpm-created `node_modules` tree as evidence that npm installation is valid.

## NestJS tooling on Node 25

NestJS 12 remains the API framework. The Nest CLI and schematics are intentionally not part of this local toolchain because their current Angular-devkit dependency excludes Node 25.

The API uses:

```text
TypeScript compiler -> dist/
Node.js 25 -> dist/main.js
```

Development watch is implemented by `apps/api/scripts/dev.mjs`, which runs `npm exec -- tsc --watch` and restarts the compiled API after a clean compilation.

Do not re-add `@nestjs/cli` or `@nestjs/schematics` without first validating Node 25 compatibility.

## PostgreSQL

Create a local database and role using your preferred PostgreSQL administration tool.

Suggested development values:

```text
host: localhost
port: 5432
database: interview
user: interview
```

Keep the password only in `.env`; never commit it.

Example connection string:

```text
postgresql://interview:CHANGE_ME@localhost:5432/interview
```

## Starting the apps

```bash
npm run registry:check
npm install
npm run dev:web
npm run dev:api
```

Or run both through Turborepo:

```bash
npm run dev
```

## Quality gate

```bash
npm run lint
npm run typecheck
npm run test
npm run build
```

## Add services only when needed

- Redis: when ephemeral state/caching/workflow features require it.
- pgvector: when semantic candidate matching begins.
- Python: when AI/media workers begin.
- LiveKit/coturn: when realtime interview development begins.

Local file artifacts are stored under `.local-data/` and are ignored by Git.
